                                                     CONSTRAINT  IN MYSQL


A constraint is a rule applied on a column to control what type of data can be stored.

🔹 What is a Constraint?

A constraint is used to:

Ensure data accuracy

Maintain data integrity

Prevent invalid data entry

🔹 Types of Constraints in MySQL
1️⃣ NOT NULL

Column cannot store NULL (empty value)

name VARCHAR(50) NOT NULL;
2️⃣ UNIQUE

All values must be different

email VARCHAR(100) UNIQUE;

✔ No duplicate emails allowed

3️⃣ PRIMARY KEY

Uniquely identifies each row
✔ Cannot be NULL
✔ Cannot be duplicate

id INT PRIMARY KEY;
4️⃣ FOREIGN KEY

Creates relationship between two tables

FOREIGN KEY (dept_id) REFERENCES departments(id);

✔ Ensures matching value exists in another table

5️⃣ CHECK

Ensures condition is true

age INT CHECK (age >= 18);
6️⃣ DEFAULT

Gives default value if not provided

status VARCHAR(20) DEFAULT 'active';
7️⃣ AUTO_INCREMENT

Automatically increases number

id INT AUTO_INCREMENT;
🔹 Example Table with Constraints
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT CHECK (age >= 18),
    status VARCHAR(20) DEFAULT 'active'
);
🔁 Most Important for Exams & Interviews

Focus on:

PRIMARY KEY

FOREIGN KEY

NOT NULL

UNIQUE

UNIQUE KEY ensures that all values in a column (or combination of columns) are different — no duplicates allowed.

It is a constraint used to maintain data integrity in a table.

1️⃣ What is UNIQUE KEY?

A UNIQUE KEY prevents duplicate values in a column.

✔ Duplicate values ❌ Not allowed
✔ NULL values ✅ Allowed (but only one NULL in most MySQL versions for single-column unique)

2️⃣ Example Without UNIQUE
CREATE TABLE students (
    id INT,
    email VARCHAR(100)
);

If you insert:

INSERT INTO students VALUES (1, 'abc@gmail.com');
INSERT INTO students VALUES (2, 'abc@gmail.com');

⚠ Duplicate email allowed (not good).

3️⃣ Example With UNIQUE KEY
CREATE TABLE students (
    id INT,
    email VARCHAR(100) UNIQUE
);

Now:

INSERT INTO students VALUES (1, 'abc@gmail.com');
INSERT INTO students VALUES (2, 'abc@gmail.com');

❌ ERROR: Duplicate entry

4️⃣ Add UNIQUE to Existing Table
ALTER TABLE students
ADD UNIQUE (email);

5️⃣ UNIQUE with Multiple Columns (Composite Unique)
CREATE TABLE orders (
    order_id INT,
    product_id INT,
    UNIQUE (order_id, product_id)
);

👉 This means:

Same order_id + product_id combination ❌ Not allowed

But order_id can repeat separately ✔

product_id can repeat separately ✔

6️⃣ Difference Between PRIMARY KEY and UNIQUE KEY
PRIMARY KEY	UNIQUE KEY
Only one per table	Multiple allowed
Cannot contain NULL	Can contain NULL
Automatically NOT NULL	NULL allowed

                                                                           CHECK CONSTAINT 

✅ CHECK Constraint in MySQL

CHECK constraint is used to restrict values in a column based on a condition.

It ensures that inserted or updated data satisfies a rule.

🔹 Basic Syntax
1️⃣ While Creating Table
CREATE TABLE users (
    id INT,
    age INT CHECK (age >= 18)
);

👉 Now age must be 18 or more
If you insert:

INSERT INTO users VALUES (1, 16);

❌ ERROR (Check constraint violated)

2️⃣ Add CHECK to Existing Table
ALTER TABLE users
ADD CHECK (age >= 18);
🔹 Example 1 – Mobile Number Length
CREATE TABLE contacts (
    id INT,
    mobile VARCHAR(15),
    CHECK (LENGTH(mobile) >= 10)
);

Now mobile must have at least 10 digits.

🔹 Example 2 – Salary Condition
CREATE TABLE employees (
    id INT,
    salary DECIMAL(10,2),
    CHECK (salary > 0)
);

Salary cannot be negative.

🔹 Column-Level vs Table-Level CHECK
✔ Column-Level
age INT CHECK (age >= 18)
✔ Table-Level
CHECK (age >= 18)

Both work similarly.

🔥 Important Points (Very Important)

CHECK works properly in MySQL 8.0.16+

MySQL checks existing data before adding CHECK

If old data violates condition → ❌ ERROR

CHECK cannot reference another table

NULL values usually pass CHECK (because NULL is unknown)

Example:

mobile VARCHAR(15) CHECK (LENGTH(mobile) >= 10)

If mobile = NULL → ✅ Allowed

🔥 Difference: CHECK vs UNIQUE
CHECK	UNIQUE
Restricts value condition	Prevents duplicate values
Example: age >= 18	Example: email must be unique
🎯 Real Interview Question

Q: Can CHECK and UNIQUE be used together?
Answer: Yes.

Example:

mobile VARCHAR(15) UNIQUE CHECK (LENGTH(mobile) >= 10)

                                                            	NAMING CONSTRAINT IN MY SQL 

Naming a Constraint in MySQL

You can give a custom name to a constraint so you can easily identify, modify, or drop it later.

By default, MySQL gives automatic names like:

contacts_chk_1

But you can define your own name.

🔹 1️⃣ Naming a CHECK Constraint
✅ While Creating Table
CREATE TABLE users (
    id INT,
    age INT,
    CONSTRAINT chk_age CHECK (age >= 18)
);

Here:

chk_age → constraint name

✅ Add CHECK to Existing Table
ALTER TABLE users
ADD CONSTRAINT chk_salary CHECK (salary > 0);
🔹 2️⃣ Naming a UNIQUE Constraint
CREATE TABLE contacts (
    id INT,
    email VARCHAR(100),
    CONSTRAINT uq_email UNIQUE (email)
);

uq_email → custom unique constraint name

🔹 3️⃣ Naming a PRIMARY KEY
CREATE TABLE students (
    id INT,
    name VARCHAR(50),
    CONSTRAINT pk_students PRIMARY KEY (id)
);
🔹 4️⃣ Naming a FOREIGN KEY
CREATE TABLE orders (
    order_id INT,
    user_id INT,
    CONSTRAINT fk_user
    FOREIGN KEY (user_id)
    REFERENCES users(id)
);
🔥 Why Naming Constraint Is Important?

If you want to drop it later:

ALTER TABLE users
DROP CHECK chk_age;

OR

ALTER TABLE contacts
DROP INDEX uq_email;

If you don’t name it, you must check the system-generated name first.

🎯 Best Practice Naming Convention
Constraint	Example Name
PRIMARY KEY	pk_tableName
UNIQUE	uq_columnName
FOREIGN KEY	fk_tableName
CHECK	chk_columnName

Example:

pk_users
uq_email
chk_salary
fk_orders_users

                                                                        ALTER IN MYSQL : 

✅ ALTER TABLE in MySQL

ALTER TABLE is used to change the structure of an existing table.

You can:

Add column

Delete column

Modify column

Rename column

Add or drop constraints

Rename table

🔹 1️⃣ Add New Column
ALTER TABLE contacts
ADD address VARCHAR(100);

🔹 2️⃣ Add Multiple Columns
ALTER TABLE contacts
ADD city VARCHAR(50),
ADD pincode INT;

🔹 3️⃣ Modify Column (Change Datatype / Add Constraint)
ALTER TABLE contacts
MODIFY mobile VARCHAR(15);

Add UNIQUE:

ALTER TABLE contacts
MODIFY mobile VARCHAR(15) UNIQUE;
🔹 4️⃣ Rename Column (Very Important)

In MySQL 8+:

ALTER TABLE contacts
RENAME COLUMN mobile TO phone;

Old method:

ALTER TABLE contacts
CHANGE mobile phone VARCHAR(15);

⚠ In CHANGE, you must write datatype again.

🔹 5️⃣ Drop Column
ALTER TABLE contacts
DROP COLUMN address;

🔹 6️⃣ Add UNIQUE Constraint
ALTER TABLE contacts
ADD CONSTRAINT uq_email UNIQUE (email);

🔹 7️⃣ Add CHECK Constraint
ALTER TABLE contacts
ADD CONSTRAINT chk_mobile
CHECK (LENGTH(mobile) >= 10);

🔹 8️⃣ Drop Constraint

Drop UNIQUE:

ALTER TABLE contacts
DROP INDEX uq_email;

Drop CHECK:

ALTER TABLE contacts
DROP CHECK chk_mobile;
🔹 9️⃣ Rename Table
ALTER TABLE contacts
RENAME TO contact_details;
🔥 Important Things

MySQL checks existing data before adding constraints

MODIFY changes datatype but keeps column name

CHANGE renames column but requires datatype

✅ RENAME and MODIFY in MySQL (Clear Difference)

RENAME changes the column name. MODIFY changes the datatype or properties.

Many students confuse these two. Let’s make it very clear 👇

🔹 1️⃣ RENAME COLUMN

👉 Used to change column name only.

✅ MySQL 8+ Syntax
ALTER TABLE contacts
RENAME COLUMN mobile TO phone;

✔ Name changes
✔ Datatype stays same

🔹 2️⃣ MODIFY COLUMN

👉 Used to change datatype, size, or constraints
👉 Column name remains same

Example
ALTER TABLE contacts
MODIFY mobile VARCHAR(20);

Here:

Name = mobile (same)

Datatype changed

🔹 3️⃣ CHANGE (Rename + Modify Together)

If you want to rename AND change datatype in one command:

ALTER TABLE contacts
CHANGE mobile phone VARCHAR(20);

⚠ Important:
You must write datatype again.

🔥 Quick Comparison Table
Command	Changes Name	Changes Datatype
RENAME	✅ Yes   	❌ No
MODIFY	❌ No	        ✅ Yes
CHANGE	✅ Yes  	✅ Yes

✅ MODIFY in MySQL

MODIFY is used to change the datatype, size, or constraints of an existing column — but NOT the column name.

🔹 Basic Syntax
ALTER TABLE table_name
MODIFY column_name new_datatype;
🔹 1️⃣ Change Datatype
Before:
mobile VARCHAR(10)
Increase size:
ALTER TABLE contacts
MODIFY mobile VARCHAR(15);

✔ Column name same
✔ Size changed

🔹 2️⃣ Add Constraint Using MODIFY

Add NOT NULL:

ALTER TABLE contacts
MODIFY mobile VARCHAR(15) NOT NULL;

Add UNIQUE:

ALTER TABLE contacts
MODIFY mobile VARCHAR(15) UNIQUE;
🔹 3️⃣ Add DEFAULT Value
ALTER TABLE contacts
MODIFY city VARCHAR(50) DEFAULT 'Patna';
🔹 4️⃣ Remove NOT NULL
ALTER TABLE contacts
MODIFY mobile VARCHAR(15) NULL;
🔥 Important Rules

1️⃣ You must write datatype again
2️⃣ Column name cannot be changed using MODIFY
3️⃣ Existing data must satisfy new constraint
4️⃣ If constraint fails → MySQL gives error

🔹 Example of Error

If column has NULL values:

ALTER TABLE contacts
MODIFY mobile VARCHAR(15) NOT NULL;

❌ Error if any row contains NULL

🔹 Difference From CHANGE
MODIFY	CHANGE
Cannot rename column	Can rename column
Must write datatype	Must write datatype
Used to alter structure	Used to rename + alter

Answer: ❌ No. It only changes datatype or constraints.  



                                                                  ✅ Relationships in MySQL


Relationships connect tables using Primary Key and Foreign Key.

In real projects (internship / companies), data is never stored in one table.
Tables are connected using relationships.

🔹 Why Relationships Are Needed?

Suppose:

One table → customers

One table → orders

Instead of storing customer details again and again in orders table,
we connect them using relationships.

🔥 Types of Relationships in MySQL

There are 3 main types:

1️⃣ One-to-One (1:1)
2️⃣ One-to-Many (1:N)
3️⃣ Many-to-Many (M:N)

1️⃣ One-to-One (1:1)

👉 One record in Table A is linked to one record in Table B.

Example:

One person → One passport

CREATE TABLE persons (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE passports (
    passport_id INT PRIMARY KEY,
    person_id INT UNIQUE,
    FOREIGN KEY (person_id) REFERENCES persons(id)
);

Here:

person_id is UNIQUE

So one person can have only one passport

2️⃣ One-to-Many (1:N) ⭐ (Most Important)

👉 One record in Table A
👉 Multiple records in Table B

Example:

One customer → Many orders

CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

Here:

One customer

Many orders

Foreign key creates relationship

3️⃣ Many-to-Many (M:N)

👉 Many records in Table A
👉 Many records in Table B

We need a third table (junction table).

Example:

Students and Courses

One student → Many courses
One course → Many students

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50)
);

CREATE TABLE student_course (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);

This is called a Junction Table.

🔥 Important Concepts
🔹 Primary Key

Uniquely identifies each row.

🔹 Foreign Key

Connects one table to another.

Example:

FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
🔹 ON DELETE & ON UPDATE (Very Important)
FOREIGN KEY (customer_id)
REFERENCES customers(customer_id)
ON DELETE CASCADE
ON UPDATE CASCADE;
CASCADE means:

If parent row deleted → child rows deleted automatically.

                                           JOIN IN MYSQL 

JOIN OPERATION IS USED TO COMBINE ROWS FROM TWO OR MORE TABLES BASED ON A RELATED COLUMN BETWEEN THEM.  


✅ JOIN in MySQL

:highlight

In real projects, data is stored in multiple tables.
JOIN helps us connect and fetch related data.

🔥 Why We Need JOIN?

Example:

Table 1: customers
customer_id	name
1	Anup
2	Rahul
Table 2: orders
order_id	customer_id	amount
101	1	500
102	1	700
103	2	300

Now suppose you want:

👉 Customer name + Order amount

We need JOIN.

🔹 Types of JOIN in MySQL

1️⃣ INNER JOIN
2️⃣ LEFT JOIN
3️⃣ RIGHT JOIN
4️⃣ CROSS JOIN

1️⃣ INNER JOIN (Most Important ⭐)

:highlight

SELECT customers.name, orders.amount
FROM customers
INNER JOIN orders
ON customers.customer_id = orders.customer_id;

Result:

name	amount
Anup	500
Anup	700
Rahul	300

Only matching records appear.

2️⃣ LEFT JOIN

:highlight

SELECT customers.name, orders.amount
FROM customers
LEFT JOIN orders
ON customers.customer_id = orders.customer_id;

If a customer has no order → amount will be NULL.

3️⃣ RIGHT JOIN

:highlight

SELECT customers.name, orders.amount
FROM customers
RIGHT JOIN orders
ON customers.customer_id = orders.customer_id;



4️⃣ CROSS JOIN

EVERY ROW FROM ONE TABLE IS COMBINED WITH EVERY ROW FROM ANOTHER TABLE .

:highlight

SELECT *
FROM customers
CROSS JOIN orders;

If 2 customers and 3 orders → 2 × 3 = 6 rows

🔥 Visual Understanding
JOIN Type	What It Returns
INNER	        Only matching data
LEFT	      All left + matched right
RIGHT	      All right + matched left
CROSS	     All combinations

👉 INNER JOIN

Q: What is difference between INNER and LEFT JOIN?
👉 INNER shows only matching rows
👉 LEFT shows all left table rows even if no match

🔥 Important Rule

INNER JOIN only returns rows where:

table1.column = table2.column

If no match → row is ignored.

SELECT c.name, o.amount

                                                                                         ✅ RIGHT JOIN in MySQL

RETURNS ALL ROWS FROM THE RIGHT (OR SECOND) TABLE AND THE MATCHING ROWS FROM THE LEFT (OR FISRT ) TABLE.




:highlight

If there is no match → NULL in left table columns.

🔹 Query
SELECT c.name, o.amount
FROM customers c
RIGHT JOIN orders o
ON c.customer_id = o.customer_id;
🔹 Result

If every order has a valid customer:

name	amount
Anup	500
Anup	700
Rahul	300

If an order had customer_id not matching:

Then name would be NULL.

🔥 Visual Difference
JOIN Type	What It Returns
INNER   	Only matching rows
LEFT    	All left + matching right
RIGHT   	All right + matching left

🎯 Easy Trick to Remember

LEFT JOIN → Left table is important
RIGHT JOIN → Right table is important

🔥 Real-Life Use

LEFT JOIN is used when:

You want all customers

Even those who didn’t place order

Find customers without orders

Example:

SELECT c.name
FROM customers c
LEFT JOIN orders o
ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;

👉 Finds customers with no orders.

🎯 Interview Question

Q: Can RIGHT JOIN be replaced by LEFT JOIN?
👉 Yes, by switching table positions.

Q: Which JOIN is used more in real projects?
👉 LEFT JOIN (more common than RIGHT JOIN)

                                                                     	ON DELETE CASCADE IN MYSQL 

✅ ON DELETE CASCADE in MySQL

:highlight

It is used with FOREIGN KEY.

🔹 Why Do We Need It?

Suppose we have:

customers (parent table)

orders (child table)

One customer → Many orders

If we delete a customer, what should happen to their orders?

👉 Without CASCADE → Error
👉 With CASCADE → Orders deleted automatically

🔥 Example Without CASCADE
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
);

Now:

DELETE FROM customers WHERE customer_id = 1;

❌ ERROR
Because orders exist for that customer.

✅ Example With ON DELETE CASCADE
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
    ON DELETE CASCADE
);

Now:

DELETE FROM customers WHERE customer_id = 1;

✔ Customer deleted
✔ All related orders automatically deleted

🔥 Real Meaning

Parent row deleted →
All child rows connected to it are deleted automatically.

🔹 Visual Example

Before delete:

Customers:

1  Anup

Orders:

101  1  500
102  1  700

After:

DELETE FROM customers WHERE customer_id = 1;

Both tables become empty for that customer.

🔥 Other Options (Important for Interview)

Besides CASCADE, there are:

Option	Meaning
ON DELETE CASCADE	Delete child rows
ON DELETE SET NULL	Set foreign key to NULL
ON DELETE RESTRICT	Prevent deletion
ON DELETE NO ACTION	Same as RESTRICT
🎯 Interview Question

Q: What is ON DELETE CASCADE?
👉 It automatically deletes related child records when a parent record is deleted.

Q: Is CASCADE dangerous?
👉 Yes, if used carelessly, it can delete large amounts of data.

🧠 When to Use It?

Use CASCADE when:

Child data has no meaning without parent
Example: order items without order

Avoid CASCADE when:

Child data must be preserved
Example: transaction history

                             ✅ Many-to-Many Relationship in MySQL

:highlight

You cannot implement it directly with just two tables.
You must create a third table (junction table).

🔥 Real Example: Students and Courses

One student → can enroll in many courses

One course → can have many students

That is Many-to-Many.

✅ Step 1: Create Main Tables
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50)
);
✅ Step 2: Create Junction Table
CREATE TABLE student_course (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
🔥 Why PRIMARY KEY (student_id, course_id)?

This prevents duplicate entries like:

1  101
1  101   ❌ duplicate

Composite primary key ensures uniqueness.

SELECT s.name, c.course_name

JOIN students s ON sc.student_id = s.student_id
JOIN courses c ON sc.course_id = c.course_id;

                                       VIEW IN MYSQL : 

✅ VIEW in MySQL

:highlight

It does NOT store data physically.
It stores only the SQL query.

🔹 Simple Meaning

View = Saved SELECT statement

Whenever you query the view →
MySQL runs the stored SELECT query.

🔥 Why Use VIEW?

✔ Simplify complex queries
✔ Hide sensitive columns
✔ Improve security
✔ Reuse logic
✔ Cleaner reporting

✅ Basic Syntax
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name
WHERE condition;

🔥 Example 1: Simple View

Suppose you have:

students table
student_id	name	marks
1       	Anup	85
2       	Rahul	60
Create View

CREATE VIEW high_marks AS
SELECT name, marks
FROM students
WHERE marks > 70;

Use View
SELECT * FROM high_marks;

Output:

name	marks
Anup	85

🔥 Example 2: View with JOIN (Very Common)
CREATE VIEW student_courses_view AS
SELECT s.name, c.course_name
FROM student_course sc
JOIN students s ON sc.student_id = s.student_id
JOIN courses c ON sc.course_id = c.course_id;

Now:

SELECT * FROM student_courses_view;

No need to write JOIN again.

🔥 Important Points

1️⃣ View does NOT store data
2️⃣ If base table changes → View result changes
3️⃣ You can use WHERE, GROUP BY, JOIN inside view
4️⃣ Views can be used like normal tables

🔹 Drop View               aapka jo bhi view bana h wah delete ho jayega 
DROP VIEW view_name;

🔹 Update View
CREATE OR REPLACE VIEW view_name AS
SELECT ...;

🔥 Interview Questions

Q: Does view store data physically?
👉 No.

Q: Can we insert data into a view?
👉 Yes, but only if it is a simple view (no GROUP BY, no JOIN usually).

Q: Why use view?
👉 Security + Simplification.

🧠 Real-Life Use in Companies

Hide salary column

Create reporting views

Create dashboard queries

API data abstraction

Now instead of writing Employees.name, you can write:

d.name

👉 Same concept:

EmployeeUNI = table name
du = alias

So:

EmployeeUNI du = EmployeeUNI AS du

Now you can write:

du.unique_id
🔥 Why we use alias (d, du)?

👉 To make query:

Shorter ✅
Cleaner ✅
Easy to read ✅
3️⃣ SELECT du.unique_id, d.name

👉 You are selecting:

du.unique_id → from EmployeeUNI table
d.name → from Employees table
4️⃣ LEFT JOIN

👉 This is very important:

LEFT JOIN means:

Take ALL data from LEFT table (Employees)
Match data from RIGHT table (EmployeeUNI)

5️⃣ ON d.id = du.id

👉 This is the condition:

Match rows where:

Employees.id = EmployeeUNI.id
